## WHAT CHANGED IN THE CODE, AND HOW EACH WAS VERIFIED

Verification method matters more than the fact; a bare "fixed" is not reusable.

* **Datum**: nine tiles carried the retired order-2 parabola. It CANNOT be undone from the
  raster — it fits dx, dy AND dz and the horizontal part was applied by resampling; on
  carlton |dxy| median 103 mm, max 304 mm, implying vertical error p90 48.4 mm against a
  44.4 mm stable_1sigma. So: re-run from clouds. Snapshot kept at
  `data/derived/_parabola_era_snapshot/` (383 MB, six sites, README).
  **CORRECTION worth keeping**: the new-minus-old DoD table is NOT the datum change alone —
  the old products also predate `ed8ab82`, which made the MEDIAN the default ground
  estimator. carlton's gen2 z_after alone moved median +244.69 mm. The estimator dominates.
* **LoD standard error** (`b643858`): `nan_to_num` set a missing epoch's variance to ZERO,
  the most optimistic value, and `cell_plane_roughness` returns NaN below 6 points — so the
  zero landed on the THINNEST cells. Plain arithmetic propagates correctly, so the right
  code is shorter. Cells that lost a limit: elba 109,894, cook 58,939, whitewater 16,304,
  mnrv 7,141, carlton 13,076, battlecreek 197.
* **Leaf-on LoD widening is now opt-in** (`e384dfa`): `factor=2.0` has NO derivation and was
  applied at every site to 5.8–40% of cells. `--leafon-lod-factor` must be passed.
* **`io.read_tile`** (`7206d52`): looked only for `scan_angle_rank`, which PF6+ DROPS — and
  every CSF cache is PF7, so every one read as **all-nadir, time zero**. Verified by the PF7
  cache and PF1 source now agreeing at ±17.00°, the scanner's half-angle. `difference_dem`
  was NOT affected (it reads `f.scan_angle * 0.006` directly) — checked, not assumed.
* **Absent strata are OMITTED, not zero-filled** (`b918699`): `stratum`, `core_forest`,
  `core_open`, `pfs_forest`, `pfs_open`. The `--without` requirement existed to compensate
  for the zero-fill; with it gone, a standard run needs no flags.
* **Unmodellable drift is NaN** (`95ba964`): not zero (a claim), not fatal (discards
  everything computable). battlecreek 89 returns, mnrv 1,079 — both verified confined to the
  swath in question.
* **Workflow staleness** (`c59af22`, `70802bb`, `b10aaa8`): products are checked against the
  CODE that made them, and by content HASH not mtime. Outputs judged by production time,
  inputs by content time — using content_time on both sides was a bug found by using it.

## THE OPEN SCIENTIFIC QUESTION — a swath tie no estimator produced

`analysis/SWATH_TIE_DEGENERACY.md` has the full evidence. battlecreek ships `1102
dz=+0.0137 m`; the pair supplying it reports **dz = −3.4640 m** from a strip 2.8 m wide by
67.3 m long, too narrow for aspect diversity, extrapolated to nadir off no lever arm. Weight
`sqrt(n)=0`, so it constrains nothing and `lstsq` hands back a minimum-norm value.

**FOUR rules tested, EVERY ONE misclassifies a real case** — do not re-walk these:

    n == 0              the rigid fallback legitimately has n=0 with a valid dz
    converged is False  kills carlton 89-90: 22,293 cells, finite dx_sigma, IMPROVED
                        scatter. Slow, not failed. Would leave 1.99% of that tile unaligned
    n_dz <= 0           too permissive: the intercept reports n_dz=36, keeps the -3.4640 m
    dtan brackets 0     kills 1012-1014: 37,436 cells, sound -0.0072 m

**Andy's criterion, which DOES separate them:** a swath already covered by another adds
overlap but no new information. Every one of the 26 swaths across six sites has exclusive
cells EXCEPT battlecreek 1102 and mnrv 6251 — the two with fabricated ties.
`coreg.swath_coverage` computes it ON THE ANALYSIS GRID (exclusivity is not scale-free:
mnrv 6251 has 165 exclusive cells at 1 m, 2 at 2 m, 0 at 5 m) and `difference_dem` records
it per swath. It RECORDS, it does not exclude: 6251 reaches 62.5% of a shared cell so could
still shift its median, and applying 1102's constant moves ONE cell by 4.9 mm.
**Andy's call, still open.** The threshold-free route is to weight the network by each
observation's own variance instead of `sqrt(n)` — that changes a property
`coregister_swaths` holds fixed on purpose.
