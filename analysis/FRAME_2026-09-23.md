## HOW THE ESTIMATOR IS TO BE USED (stated to Andy 2026-10-16; he asked that it be recorded)

The half-sample mode REPLACES THE MEDIAN as the per-epoch ground estimate at each grid cell.
Nothing else in the chain changes.

* **Operates on** the slope-normal residuals the pipeline already computes: each
  near-ground return's height above the cell's local fitted surface. The pipeline takes
  their median today (``ground_q = 0.50``); the mode takes the densest cluster, so a
  vegetation tail above the ground does not drag the estimate up.
* **gen2**: per 5 m cell at full density (~200-300 near-ground returns). The count-bias
  curve says the mode is unbiased there (steps 3-4 in `CONTROL_MODE_NULL_CHECK.md`).
* **gen1 on the flat floodplain**: pool the 3x3 neighbourhood's RESIDUALS first (~144
  returns), then take the mode. Pooling is on residuals, not elevations, so it mixes offsets
  and not relief. Count bias ~1 mm at 144. The ground estimate's effective resolution drops
  to 15 m there while the grid stays at 5 m.
* **The DoD** is gen2's mode ground minus gen1's mode ground, star-only registration
  unchanged. NO cross-epoch coefficient enters anywhere. The control marks were used ONLY
  as a null check on the estimator; nothing was fitted to them and no correction function
  came out of them (Andy asked both questions explicitly, 2026-10-16).
* **Must NOT go to hillslopes yet.** A steep cell's ground population is itself broad; the
  mode was checked against a vegetation tail, not against relief. The terrain-slope test
  comes first.
* **What it is today**: analysis scripts only. The pipeline's ground estimator has NOT been
  changed; the coarsened result corrected the existing DoD cell by cell rather than
  rebuilding the product. Building it into the pipeline is a separate step and is Andy's
  call.
* **What it will not do**: remove the ~66 mm of spread-quartile structure that remains in
  the most-vegetated floodplain cells. That residual is not a count problem (measured) and
  the mode has no mechanism for it.

## GOTCHAS THAT WILL BITE

* `data/before_battlecreek/gen1_4tile.laz` has **point_source_id = 0 and gps_time = 0 on all
  24,642,050 points**. Use the four quarter-tiles.
* `registration.read_swath_alignment` REFUSES a star product that does not record
  `per_swath_star_frame_dxdydz_m` -- the other key holds align_swaths'
  SOLVED-BUT-NOT-APPLIED diagnostic and using it would correct by a shift never applied.

  quantiles unchanged in expectation; an earlier version reported that null as a result.
* The near-ground cube (`nearground_cells_sn.npz`) covers only ~30% of the flat floodplain
  -- a file footprint, not a population. Never fit inside it and call it a population.

* **A half-sample mode on BINNED values must break ties symmetrically.** `np.argmin` on the
  window widths takes the first tied window and biases the mode low by ~sigma/2 (synthetic:
  -29.5 mm at sigma 60, -58.1 at sigma 150, 20 mm bins). Use `analysis/hsm.py`; never
  re-implement it inline. Prefer the raw values when they exist (`d_mm_corr` is raw).
